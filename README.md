# 최종윤 ♥ 임세희 모바일 청첩장

## 1. GitHub Pages 배포 방법
1. 이 폴더 전체를 새 GitHub 저장소에 업로드합니다.
2. 저장소 Settings → Pages → Branch를 `main` (root)로 설정합니다.
3. 몇 분 뒤 `https://<아이디>.github.io/<저장소명>/` 주소로 접속됩니다.

## 1-1. 카카오톡/문자로 링크 보낼 때 뜨는 미리보기 이미지 바꾸기
카톡 등으로 링크를 보내면 뜨는 제목/설명/사진은 `index.html` 맨 위쪽의
`<meta property="og:...">` 태그들이 결정합니다.

1. GitHub Pages 배포를 마친 뒤(1번 단계), 실제 접속 주소를 확인합니다.
   (`https://<아이디>.github.io/<저장소명>/` 형태)
2. `index.html`에서 아래 두 줄을 찾아 `YOUR-GITHUB-USERNAME`, `YOUR-REPO-NAME` 부분을
   실제 주소로 바꿔주세요.
   ```html
   <meta property="og:image" content="https://YOUR-GITHUB-USERNAME.github.io/YOUR-REPO-NAME/images/deco/og-image.jpg" />
   <meta property="og:url" content="https://YOUR-GITHUB-USERNAME.github.io/YOUR-REPO-NAME/" />
   ```
3. 지금은 봉투 위에 "JJONGPA ♥ SAY"가 적힌 `images/deco/og-image.jpg`가 미리보기
   사진으로 지정되어 있습니다. 다른 사진으로 바꾸고 싶으면 `og:image` 경로만
   원하는 이미지 파일 경로로 바꾸면 됩니다.
4. 카카오톡은 한 번 가져온 미리보기를 한동안 캐싱하기 때문에, 바꾼 직후에는
   이전 화면이 잠깐 남아있을 수 있습니다. 시간이 좀 지나거나 URL 뒤에
   `?v=2`처럼 임의의 값을 붙여서 테스트하면 바로 확인할 수 있습니다.

## 2. 이미지 교체 방법 (가장 자주 할 작업)
- `images/main/1.jpg`, `2.jpg` … : 첫 화면(커버)용 사진
- `images/story/1.jpg` ~ : 우리들의 이야기 카드 사진 (js/config.js의 `storyData` 순서와 매칭)
- `images/gallery/1.jpg` ~ `12.jpg` : 사진 갤러리 (숫자 순서대로 존재하는 파일만 자동으로 보여줍니다)

파일만 교체하면 코드는 건드릴 필요 없습니다. 확장자가 `.jpg`가 아니어도(`.jpeg`, `.png`, `.webp`)
같은 이름이면 자동으로 찾아서 보여줍니다.

## 3. 폰트 - 이미 적용되어 있습니다
- `fonts/wedding-font/NanumNeuRisNeuRisCeR.TTF` : 본문/기본 폰트
- `fonts/title-font/THE_Nakseo.ttf` : "사진", "달력", "우리들의 이야기" 같은 섹션 제목 전용 폰트

다른 폰트로 바꾸고 싶으면 해당 폴더에 새 폰트 파일을 넣고, `css/style.css` 상단의
`@font-face` 안 `src` 경로와 `--font-body` / `--font-accent` / `--font-title` 값을 바꿔주세요.

### 글씨 크기를 전체적으로 더 키우고 싶다면
`css/style.css` 파일 맨 위쪽, `html { font-size: 16px; }` 이 한 줄만 찾아서
숫자를 올리면(예: 18px, 20px) 사이트 전체 글자 크기가 비율 그대로 다 같이 커집니다.
(다른 모든 글자 크기가 이 기준값에 대한 비율(rem 단위)로 되어 있어서, 이 값 하나만
바꾸면 됩니다. 특정 부분만 따로 더 키우고 싶으면 `css/style.css`에서 해당 요소를
검색해(예: 섹션 제목은 `.section-title`) `font-size` 줄만 수정하면 됩니다.)

## 5. 정보/텍스트 수정
`js/config.js` 파일 하나만 수정하면 됩니다.
- 이름, 날짜, 웨딩홀, 주소, 지도 링크, 인사말, 관리자 코드 전부 이 파일에 있습니다.
- 버스/주차 안내처럼 여러 줄인 항목은 문자열 안에 `\n`으로 줄바꿈을 넣으면 그대로 줄바꿈되어 표시됩니다.
- **계좌(마음 전하실 곳)**: `WEDDING_INFO.accounts` 배열에 원하는 만큼 추가/삭제할 수 있습니다.
  `group`(신랑측/신부측), `label`(버튼에 보일 이름), `bank`/`account`/`holder`를 채우면
  아코디언 버튼이 자동으로 생깁니다. 예: 신랑 본인 + 신랑 아버지 + 신랑 어머니처럼 같은
  `group` 값을 가진 항목은 같은 묶음으로 표시됩니다.
- **티맵 버튼**: 비워두면(`tmapUrl: ""`) 웨딩홀 이름으로 티맵 앱 안에서 자동 검색되는
  링크가 만들어집니다. 좌표를 알고 있으면 `"tmap://route?goalx=경도&goaly=위도&goalname=이름"`
  형태로 직접 넣으면 더 정확하게 연결됩니다. (티맵은 앱이 설치되어 있어야 열립니다.)

> **달력 이미지 안내**: "달력" 섹션은 보내주신 손그림 달력 이미지(`images/deco/calendar-card.png`)를
> 그대로 사용합니다. 이 이미지 자체에 2027년 4월이 그려져 있어서, 결혼 날짜(월)를 바꾸시면
> 이미지도 새로 만들어서 교체해야 합니다. D-DAY 숫자는 이미지와 별개로 계속 자동 계산됩니다.

> **방명록 안내**: 축하 메시지는 연한 청록색 카드 형태로 보이고, 옆으로 스와이프해서
> 넘겨볼 수 있습니다. 카드 오른쪽 위 ✕ 버튼은 그 화면에서만 안 보이게 잠깐 치워두는
> 용도로, 실제로 삭제되지는 않습니다(새로고침하면 다시 보입니다). 메시지는 최대 80자로
> 제한되어 있습니다.

## 6. Supabase 연동 방법 (축하메시지 / 참석여부 / 관리자 확인)

### 6-1. Supabase 프로젝트 만들기
1. https://supabase.com 에서 무료 계정 생성 → New project
2. 프로젝트가 만들어지면 왼쪽 메뉴 **SQL Editor** 클릭

### 6-2. 테이블/보안정책 설치
1. 이 저장소의 `supabase/schema.sql` 파일 내용을 전체 복사
2. SQL Editor에 붙여넣고 **Run** 실행
   - `guestbook_messages`(방명록), `rsvps`(참석여부) 테이블이 생성됩니다.
   - 방명록은 누구나 읽고 쓸 수 있게, 참석여부는 "쓰기만" 가능하고
     "조회"는 관리자 코드가 맞아야만 서버(Postgres 함수) 안에서 처리되도록
     보안 정책(RLS)이 함께 설정됩니다.
3. 파일 안의 `crypt('0418', gen_salt('bf'))` 부분에서 `0418`을
   실제로 사용할 관리자 코드로 바꾼 뒤 실행하세요. (숫자/문자 모두 가능)
   - 나중에 코드를 바꾸고 싶으면 파일 맨 아래 주석 처리된 update문만
     다시 실행하면 됩니다.

> **이미 예전 버전의 `schema.sql`을 실행해서 Supabase를 사용 중이라면**
> 참석여부 폼에 전화번호(동명이인 확인용)가 추가되어 `rsvps` 테이블 구조가
> 살짝 바뀌었습니다. `schema.sql` 최신 내용을 그대로 다시 한 번 SQL Editor에서
> 실행해주세요 — 기존 데이터는 안전하게 유지되고 `phone` 컬럼만 추가됩니다.

### 6-3. 연결 정보 - 이미 입력되어 있습니다
`js/config.js`에 `SUPABASE_URL`/`SUPABASE_ANON_KEY`가 이미 채워져 있습니다.
(URL과 anon key는 공개되어도 안전한 값입니다 — 실제 데이터 보호는 RLS 정책이 담당합니다.)
다른 프로젝트로 바꾸고 싶으면 Supabase 대시보드 → **Project Settings → API**에서
`Project URL`과 `anon public` 키를 복사해 같은 자리에 덮어쓰면 됩니다.

### 6-4. 관리자 확인 방법
청첩장 맨 아래 "참석 여부 확인" 버튼 → 6-2에서 설정한 코드 입력
→ 통과 시에만 전체 응답 통계와 목록이 보입니다. 코드가 틀리면
서버에서 바로 거절되며 데이터가 전혀 내려오지 않습니다.

### 6-5. 축하 메시지/참석 여부 등록이 "실패했습니다"로 뜰 때 확인할 것
지금은 실패 메시지에 실제 오류 내용이 함께 표시되도록 고쳐뒀습니다
(예: "메시지 등록 실패: ..."). 브라우저에서 F12(또는 우클릭 → 검사) →
**Console** 탭을 열고 다시 시도해보면 더 자세한 오류가 보입니다. 자주 나오는 원인:

1. **`supabase/schema.sql`을 아직 실행하지 않음** → 6-2 단계를 SQL Editor에서 처음부터
   끝까지 한 번 실행해주세요. (테이블 자체가 없으면 항상 실패합니다.)
2. **`permission denied for table ...` (코드 42501)** → RLS 정책은 있지만
   Postgres 테이블 자체의 권한(GRANT)이 없는 경우입니다. **`supabase/fix-permissions.sql`**
   내용을 SQL Editor에 붙여넣고 실행하면 바로 해결됩니다. (이미 테이블이 있는 상태에서
   이 파일만 실행하면 되고, 테이블을 다시 만들지 않아도 됩니다.)
3. **Supabase 프로젝트가 잠들어 있음** → 무료 프로젝트는 일정 기간 사용이 없으면
   자동으로 일시 정지됩니다. Supabase 대시보드에 접속해 프로젝트가 활성 상태인지
   확인해주세요.
4. **RLS 정책 오류(에러 메시지에 "row-level security" 포함)** → `schema.sql`의
   `guestbook public insert` / `rsvp public insert` 정책 부분이 정상적으로
   만들어졌는지 SQL Editor에서 다시 실행해 확인해주세요.
5. **글자 수 제한 초과** → 이름 10자, 메시지 80자 제한이 있습니다. DB 쪽 제약
   (`char_length(name) <= 20` 등)과 프론트 제한이 다르진 않은지 `schema.sql`과
   `index.html`의 `maxlength` 값을 비교해보세요.

이 중에서 해결이 안 되면 Console에 뜨는 정확한 오류 문구를 알려주시면 바로 원인을
짚어드릴 수 있습니다.

## 7. 실제 지도 화면 넣기 (카카오맵)

⚠️ 예전에는 네이버 지도에서도 "홈페이지에 담기(퍼가기)"로 iframe 코드를 바로 뽑을 수
있었는데, 네이버 지도가 최근 이 기능을 없앴습니다(v5 지도는 블로그/카페 공유만 지원).
그래서 실제로 움직이는 지도 화면은 **카카오맵**으로 넣고, 네이버지도/카카오맵/티맵은
그대로 "바로가기" 버튼 3개로 남겨뒀습니다.

1. **`https://map.kakao.com`** 에 **PC(데스크탑) 웹브라우저**로 접속합니다.
   (⚠️ 모바일에서는 이 기능이 안 보입니다 — 꼭 컴퓨터로 열어주세요. `place.map.kakao.com`
   장소 상세 페이지에도 없으니, 지도 메인 화면에서 검색해야 합니다.)
2. 왼쪽 위 검색창에 웨딩홀 이름이나 주소를 입력해 검색합니다.
3. 검색 결과에서 해당 장소를 클릭하면 지도에 표시되고, 공유/내보내기 아이콘이 나타납니다.
4. **HTML 태그 복사**를 선택하고, 지도 크기 등을 조정한 뒤 **소스 생성하기**를 클릭합니다.
5. 나오는 소스코드는 `<a>`와 `<img>` 태그로 되어 있습니다. 그 안에서 2가지만 찾으면 됩니다.
   - `<img ... src="https://staticmap.kakao.com/...">` → 이 **src 주소**를 복사
   - `<a href="https://map.kakao.com/?urlX=...">` → 이 **href 주소**를 복사
6. `js/config.js`에서 아래 두 값을 방금 복사한 주소로 각각 교체합니다.
   ```js
   kakaoMapUrl: "https://map.kakao.com/?urlX=...",   // <a href>
   kakaoStaticMapImageUrl: "https://staticmap.kakao.com/...", // <img src>
   ```
7. 저장 후 업로드하면 실제 카카오맵 지도 이미지가 보이고, 클릭하면 카카오맵으로 연결됩니다.
   (아직 설정 전이면 "지도 연결 준비 중"이라는 안내만 표시됩니다.)

### 그래도 꼭 네이버 지도 화면을 넣고 싶다면
네이버는 이제 **네이버 클라우드 플랫폼(NCP)**에 가입하고 Maps API Client ID를
발급받아 자바스크립트로 직접 지도를 그려야 합니다. 계정 가입과 결제수단 등록이
필요해서 번거롭습니다 — 필요하시면 말씀해주세요, 그 방식으로 이어서 연동해드릴게요.

## 8. Google Drive 사진 업로드 연동 ("스냅 작가가 되어주세요")

프론트엔드에서 Drive에 직접 파일을 쓸 수는 없어서, 중간에 **Google Apps Script 웹앱**을
하나 배포해 "사진을 받아서 내 Drive 폴더에 저장"하는 역할만 맡깁니다.
Google 계정 인증정보는 이 스크립트 안에만 있고, 프론트엔드나 GitHub에는 전혀 노출되지 않습니다.

### 8-1. 저장할 Drive 폴더 만들기
1. Google Drive에서 사진을 모아둘 폴더를 하나 만듭니다. (예: `우리 결혼식 스냅사진`)
2. 폴더를 열고 주소창의 `.../folders/` 뒤에 있는 긴 문자열(폴더 ID)을 복사해둡니다.

### 8-2. Apps Script 배포
1. https://script.google.com 접속 → 새 프로젝트
2. 기본 생성된 `Code.gs` 내용을 지우고, 이 저장소의 `apps-script/Code.gs` 내용을 통째로 붙여넣습니다.
3. 코드 상단의
   - `FOLDER_ID` → 8-1에서 복사한 폴더 ID로 교체
   - `UPLOAD_TOKEN` → 원하는 값으로 교체 (예: `wedding0418`)
4. 오른쪽 위 **배포 → 새 배포**
   - 유형: **웹 앱**
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자** (하객이 로그인 없이 업로드할 수 있어야 하므로)
5. 배포 후 나오는 **웹앱 URL**을 복사해둡니다. (`https://script.google.com/macros/s/.../exec` 형태)
6. 처음 배포할 때 Google이 "확인되지 않은 앱" 경고를 띄울 수 있는데, 본인 계정으로
   만든 스크립트이므로 "고급 → 이동(안전하지 않음)"을 눌러 권한을 승인하면 됩니다.

### 8-3. 프론트엔드 연결
`js/config.js`의 `PHOTO_UPLOAD` 값을 수정합니다.
```js
const PHOTO_UPLOAD = {
  appsScriptUrl: "https://script.google.com/macros/s/여기에배포URL/exec",
  uploadToken: "wedding0418", // Code.gs의 UPLOAD_TOKEN과 반드시 동일하게
  maxFileSizeMB: 15,
  maxFiles: 10,
};
```
저장 후 GitHub에 올리면 실제로 하객이 올린 사진이 Drive 폴더에 쌓입니다.

### 참고
- `UPLOAD_TOKEN`은 비밀번호라기보다 "무작위 스팸 업로드 방지용 가벼운 장치"입니다.
  실제 보안은 Google 계정 권한(스크립트 소유자만 Drive에 쓸 수 있음)이 담당합니다.
- 업로드 용량이 매우 많아질 것으로 예상되면(수백 장 이상) Apps Script 대신
  Supabase Storage 같은 전용 파일 저장소로 바꾸는 것도 고려할 수 있습니다.

## 8-1. 첫 로딩 속도 관련 안내

이번에 아래 항목들을 고쳐서 첫 로딩이 더 빨라지도록 했습니다.
- 폰트 파일을 용량이 큰 TTF 대신 더 작은 WOFF2로 변환 (본문 폰트 5MB → 2.5MB,
  제목 폰트 800KB → 156KB). 최신 브라우저는 WOFF2만 받아가므로 실제 체감 속도가
  빨라집니다.
- Google Fonts를 불러오던 코드(`@import`)를 제거했습니다 — 이 한 줄이 있으면
  브라우저가 그 폰트를 다 받아올 때까지 화면 전체 렌더링이 늦어질 수 있었습니다.
- `<script>` 태그들에 `defer`를 붙여서, 스크립트들이 순서대로 하나씩 막혀서
  받아지는 대신 동시에 받아지도록 했습니다.
- 첫 화면(커버) 사진을 "존재하는지 미리 확인 후 다시 보여주기" 방식에서
  "바로 화면에 시도하고 실패하면만 다른 확장자로 재시도" 방식으로 바꿔서
  불필요한 중복 다운로드를 줄였습니다.
- 스크롤해야 보이는 사진(우리들의 이야기, 갤러리)은 화면에 들어올 때만
  불러오도록(`loading="lazy"`) 처리했습니다.

**가장 큰 영향을 주는 건 실제로 업로드하시는 사진 파일 용량입니다.** 커버/메인 사진은
휴대폰 카메라 원본을 그대로 올리면 장당 5~10MB가 넘는 경우가 많아 로딩이 느려집니다.
아래처럼 준비해서 올리시는 걸 추천드려요.
- 가로 1200~1600px 정도로 리사이즈
- JPG 품질 80% 안팎으로 압축 (사진 1장당 200KB~500KB 목표)
- squoosh.app 같은 무료 웹사이트에 사진을 넣기만 하면 쉽게 리사이즈/압축할 수 있습니다.

## 9. 현재 상태 요약

| 기능 | 현재 상태 |
|---|---|
| 축하 메시지 (스와이프 카드) / 참석 여부 | ✅ Supabase 연동 완료 (연결 정보 이미 입력됨) |

| 배경음악 | ✅ 적용 완료 (오른쪽 아래 토글 버튼) |
| 사진 갤러리 | ✅ 가로 스크롤 카드 + 클릭 시 확대(라이트박스) |
| 디자인 디테일 | 실제 사진 반영, 색감/여백 등 세부 조정은 계속 진행 중 |
